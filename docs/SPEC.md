# SPEC — Đọc Song Ngữ v1 (bilingual reader: Chinese · Japanese · Korean · English → Vietnamese)

Audience: the coding workers (Codex, Haiku). Everything needed is here; do not guess beyond it. UI text is Vietnamese (strings given below). Code comments may be English or Vietnamese.

## 0. Product in one paragraph
A super-light reading app for a Vietnamese learner. It suggests ONE article at a time (news, Wikipedia, literature/novels, historical documents; topics: politics, history, literature, world) from built-in sources in 4 languages (zh, ja, ko, en). The source pool refreshes daily. The reader shows each sentence as a block: original text with readings ABOVE it (`<ruby>`: furigana / pinyin / Korean romanization; none for English) and the translation BELOW it (Vietnamese by default, user-selectable). Tapping a word (when "Tra từ" is ON) opens a small popup: reading, part of speech, meanings (offline open-source dictionary + online quick translation). Word segmentation and part-of-speech colouring are toggleable. When the user reaches the last sentence they can press "Đã đọc xong": the app stores ONLY the link + title forever (durable ledger), deletes the cached article, and never suggests that link again. A pasted link can be read the same way. Two builds share one code base: a PC build (browser window + tiny local Python server) and an Android APK (Capacitor). No sync between devices; each device keeps its own data.

## 1. Architecture
- **One web core** in `web/` (plain HTML/CSS/ES modules, NO bundler, NO framework). All logic lives here: sources, extraction, sentence splitting, NLP, translation, recommendation, storage, dictionaries, UI.
- **PC shell**: `pc/server.py` (Python 3 standard library ONLY) serves `web/`, provides `/proxy` (fetch any URL on behalf of the page, bypassing CORS) and `/api/history` (durable ledger file `data/da_doc.jsonl`). `run.bat` starts it and opens `msedge --app=http://127.0.0.1:8765/`.
- **Android shell**: Capacitor (config already in `capacitor.config.json`, `webDir: "web"`, global fetch patch DISABLED). External HTTP goes through `CapacitorHttp.request(...)` called explicitly; local assets (vendor files, kuromoji dictionary) load with normal fetch/XHR from `https://localhost/`.
- All platform differences are confined to `web/core/net.js` (network) and `web/core/store.js` (durable ledger + export/import). Everything else is platform-agnostic.
- Platform detection: `IS_NATIVE = !!(globalThis.Capacitor?.isNativePlatform?.())`. Plugins on native are obtained WITHOUT npm imports: `Capacitor.registerPlugin('Filesystem')`, `'Share'`, `'App'`; `Capacitor.Plugins.CapacitorHttp` (or `registerPlugin('CapacitorHttp')`). Code defensively (feature-detect; never crash on PC).
- Node (tests/smoke) must be able to import core modules: no top-level DOM access in core/nlp/sources modules; dependencies (tokenizers, DOMParser, net implementation) are injected or configured.

## 4. Data contracts (LOCKED)
### 4.1 Article (stored in IndexedDB `articles`, keyed by `id`)
```json
{"id":"a1b2c3d4e5f6a7b8","url":"https://…","canon":"https://…","lang":"ja","source_id":"nhk-seiji","target_lang":"vi",
 "status":"ready","error":null,"created_at":"ISO","fetched_title":"…",
 "title": S,
 "blocks":[{"type":"h","sentences":[S]},{"type":"p","sentences":[S,S]}],
 "stats":{"chars":3400,"sentences":52},
 "progress":{"translated":30,"total":52,"last_read":11,"tr_state":"running|done|paused"}}
```
Sentence `S`:
```json
{"i":0,"text":"政治を学んだ。",
 "tokens":[{"s":"政治","r":"せいじ","w":0},{"s":"を","w":1},{"s":"学","r":"まな","w":2},{"s":"ん","w":2},{"s":"だ","w":3},{"s":"。"}],
 "words":[{"lemma":"政治","pos":"n","reading":"せいじ"},{"lemma":"を","pos":"p"},{"lemma":"学ぶ","pos":"v","reading":"まなんだ"},{"lemma":"だ","pos":"p"}],
 "tr":"Đã học chính trị." }
```
- `id` = first 16 hex chars of SHA-1 of `canon` (WebCrypto `crypto.subtle.digest`, works in Node too).
- `s` required. `r` = reading shown above `s` (present only when useful). `w` = index into `words`; punctuation/whitespace tokens have no `w`. `words[k].pos` ∈ `n` (danh từ) · `v` (động từ) · `a` (tính từ/trạng từ) · `p` (hư từ: trợ từ/giới từ/liên từ/trợ động từ) · `x` (khác). `words[k].reading` optional (ja: hiragana of the whole token; zh: pinyin syllables joined by spaces; ko: romanization).
- **Invariant (tested):** concatenation of all `tokens[].s` === `text`.
- `i` runs 0..N-1 across the whole article in reading order; the title sentence has `i = -1` and is not counted in `total`.
- `tr` is `null` until translated.

### 4.3 Durable ledger (the "forever" history)
- One JSON object per line: `{"url","canon","title","title_tr","lang","source_id","finished_at"}` (UTF-8, `\n`).
- PC: `data/da_doc.jsonl` via `POST /api/history` (append + fsync) and `GET /api/history` (all entries, deduped by canon).
- Android: `Filesystem.appendFile({path:'da_doc.jsonl', directory:'DATA', encoding:'utf8'})`; best-effort copy appended to `DocSongNgu/da_doc.jsonl` in `DOCUMENTS` (recursive; wrap in try/catch; report status in Settings).
- On startup: read the ledger; add any entry missing from IndexedDB `history` (rebuild). The ledger is never truncated by the app.
- Export: JSON array file (PC: browser download; Android: write to cache dir then `Share.share({files:[uri]})`). Import: `<input type=file accept=".json,.jsonl">`, merge entries missing by canon (append them to the ledger too).

### 4.5 `web/dicts.json` (array) and supported formats
```json
{"lang":"zh","id":"cvdict","name":"CVDICT Trung–Việt","gloss_lang":"vi","license":"CC BY-SA 4.0","homepage":"…","url":"https://…",
 "url_resolver":null,"format":"cedict","compressed":"none","zip_entry":null,"columns":null,"sep":null,"sense_sep":null,"skip_lines":0,
 "cors":true,"size_mb":12.3,"entries":123456}
```
- `format` ∈ `cedict` (lines `Trad Simp [pin1 yin1] /sense/sense/`, `#` comments; store head=Simp, alts=[Trad] if different, reading = pinyin converted to tone marks), `jmdict_simplified` (JSON `words[]`: head = first kanji text or first kana text, alts = other kanji + kana texts, reading = first kana text, pos = first sense's first partOfSpeech mapped, senses = each sense's English glosses joined by "; ", max 8), `tsv` (per `columns`, `sep`, `sense_sep`, `skip_lines`).
- `compressed` ∈ `none` | `gzip` | `zip` (+ `zip_entry`). `url_resolver` null or `{"github_latest":"owner/repo","asset_regex":"…"}` (resolve via `https://api.github.com/repos/<repo>/releases/latest`).
- `cors: true` → download with plain `fetch`; else via `net.fetchBytes` (proxy / CapacitorHttp) on the MAIN thread, then transfer the ArrayBuffer to `worker_dict.js` for decompress + parse + store (workers cannot call Capacitor plugins).

## 5. Module responsibilities (core)
- `bus.js`: tiny EventTarget bus. Events: `article-updated` {id}, `suggestion-changed`, `refresh-status`, `dict-progress` {id,phase,pct}, `toast` {text,kind}.
- `db.js`: promise wrapper over IndexedDB (open/upgrade, get/put/delete/getAll/index queries, batch put in one transaction). Works with `fake-indexeddb` in Node.
- `net.js`: `configureNet({mode:'pc'|'native'|'node'})` (auto-detect in browser); `fetchBytes(url,{method,headers,body,timeoutMs,direct})` → `{status, headers, bytes:Uint8Array, finalUrl, contentType}`; `fetchText(url,opts)` (decodes with charset from Content-Type → BOM → `<meta charset>`/`http-equiv` sniff of first 4 KB → utf-8; supports shift_jis, euc-jp, gbk/gb18030, big5, euc-kr via TextDecoder); `fetchJSON`. Retries 429/5xx with backoff 1 s, 2 s, 4 s (max 3). Timeout 20 s. `direct:true` uses plain `fetch` (for CORS-enabled APIs: Wikipedia/Wikisource API with `origin=*`, Wikimedia REST, raw.githubusercontent.com). PC mode non-direct → `/proxy` (see §8). Native mode non-direct → `CapacitorHttp.request({url, method, headers, data, responseType:'arraybuffer', connectTimeout, readTimeout})`; binary `data` comes back base64 → decode. Node mode → global `fetch`. Send header `Api-User-Agent: DocSongNgu/0.1 (personal reading app)` to Wikimedia hosts. Use a browser-like `User-Agent` in proxy/native requests.
- `store.js`: ledger append/read, export, import (see 4.3), PC vs native vs node (node: file in a temp dir given by config).
- `urlnorm.js`: `canon(url)`: lowercase scheme+host, force `https:`, drop `#fragment`, drop `utm_*`/`fbclid`/`gclid`, drop trailing `/` (except root), `m.`/`mobile.` subdomain → base host (e.g. `ja.m.wikipedia.org` → `ja.wikipedia.org`), decode-then-encode path consistently. The ORIGINAL url is kept for fetching; `canon` is only an identity key.
- `langdetect.js`: `detectLang(text, htmlLangHint)` → kana ratio ≥ 0.03 → `ja`; Hangul ratio ≥ 0.2 → `ko`; Han ratio ≥ 0.2 → `zh`; Latin → `en`; use the hint when ambiguous.
- `extract.js`: `extractArticle(url, {lang?, sourceKind?})` → `{url, finalUrl, title, lang, blocks:[{type:'h'|'p', text}]}` (see §6.1).
- `segment.js`: `splitSentences(text, lang)` → string[] (see §6.2).
- `article.js`: `openArticle(url, meta)` → id. Pipeline: canon → id → reuse ready article if present → extract → zh script conversion (opencc, per `zh_script`) → split → NLP (`nlp/client.js`) → save Article (status ready, all `tr:null`) → emit → start background translation (title first, then blocks in order) updating the stored article and emitting `article-updated` after each batch. Truncate articles above 60 000 characters (append a final paragraph "(Bài quá dài — đã cắt bớt phần cuối.)"). Errors → status `error` with Vietnamese message.
- `translate.js`: providers + batching (§6.7); `translateBatch(texts, src, tgt)`; `quickLookup(text, src, tgt)` → `{tr, dict:[{pos, terms[]}]}` (Google `dt=t&dt=bd&dj=1`); language code map: zh→`zh-CN` (or `zh-TW` when displaying Traditional), ja, ko, en, vi, …
- `recommend.js`: `getSuggestion(filterLang)`, `skipSuggestion()`, `finishArticle(id)`, `abandonArticle(id)` (§6.8).
- `jobs.js`: `maybeRefresh(force)` (§6.9), `prefetchSuggestion()`, startup sequence.
- `lookup.js`: `lookupWord({lang, lemma, surface, reading})` (§6.10).
- `dicts.js`: list packs (dicts.json + dict_meta), install (resolve URL → download → worker parse/store with progress), remove (delete by `pack`).
- `settings.js`: get/set with defaults, change events, apply CSS classes on `<body>`.
- `nlp/client.js`: main-thread facade `analyze(lang, sentences[], opts)` → `[{tokens, words}]`; lazily spawns `worker_ja.js` (classic) / `worker_zh.js` (module); ko/en run on the main thread; emits a "loading tokenizer" state for the UI. `nlp/ja.js`, `zh.js`, `ko.js`, `en.js` are PURE functions with injected dependencies (tokenizer / tag / pinyin / dictionary checker) so tests run them in Node.

## 6. Algorithms and rules
### 6.1 Extraction
- **Wikipedia** (`*.wikipedia.org/wiki/…`): API `https://<wiki>.wikipedia.org/w/api.php?action=query&prop=extracts&explaintext=1&exsectionformat=wiki&redirects=1&titles=<title>&format=json&formatversion=2&origin=*` (direct). Lines `== H ==` (any level) → `h` blocks; other non-empty lines → `p` blocks. Drop each section whose heading (trimmed) is in: en: References, Notes, See also, External links, Further reading, Bibliography, Sources, Citations, Footnotes · ja: 脚注, 注釈, 出典, 参考文献, 関連項目, 外部リンク, 参照 · zh (both scripts): 参考资料, 參考資料, 参考文献, 參考文獻, 注释, 注釋, 外部链接, 外部連結, 参见, 參見, 脚注, 腳註, 延伸阅读, 延伸閱讀 · ko: 각주, 참고 문헌, 같이 보기, 외부 링크, 참조, 더 읽어보기.
- **Wikisource** (`*.wikisource.org/wiki/…`): `action=parse&page=<title>&prop=text&format=json&formatversion=2&origin=*` → HTML → remove `.ws-noexport`, `#headerContainer`, `.headertemplate`, `.mw-editsection`, `sup.reference`, `ol.references`, `table`, `style`, `script` → walk `.mw-parser-output` block elements (h2–h4 → h; p, dd, li, div.poem lines → p).
- **Aozora** (`www.aozora.gr.jp/cards/…/files/*.html`): fetch bytes, decode (Shift_JIS unless meta says otherwise) → `div.main_text`: remove `rt`, `rp`, `.notes`; `<br>` = line break; paragraphs = lines (Aozora paragraphs start with "　"); `.o-midashi/.naka-midashi/.ko-midashi` → h. Title = `h1.title`; author = `h2.author`.
- **Everything else** (RSS items, pasted links): fetchText → DOMParser → `new Readability(doc).parse()` → content HTML → walk blocks (h1–h4 → h; p, li, blockquote → p; skip figure, figcaption, aside, nav, table, form, button). If Readability returns null or < 300 characters → fallback: all `p/h2/h3/li` with text length ≥ 40 (the old app's fallback). Title: Readability title, else `og:title`, else `<title>`, minus site suffix after ` - `, ` | `, ` – ` when the suffix is short (≤ 20 chars).
- Clean: collapse whitespace (keep CJK text intact), drop empty blocks and boilerplate lines (exact matches): "Advertisement", "Share", "Read more", "広告", "关注我们", "광고", "기자", "©".
- Language: source lang if known, else `detectLang(text, <html lang>)`.

### 6.2 Sentence splitting
- ja/zh: split after any of `。！？!?…` plus following closing marks `」』）】〉》"'”’` (kept with the sentence); also at line breaks. Merge fragments shorter than 2 characters into the previous sentence.
- ko/en: split after `.!?…` (+ closing quotes/brackets) followed by whitespace and then an uppercase letter, digit, quote, or (ko) any Hangul. Do NOT split after abbreviations: Mr, Mrs, Ms, Dr, Prof, Sr, Jr, St, Mt, Gen, Gov, Sen, Rep, Lt, Col, Capt, Inc, Ltd, Co, Corp, vs, etc, e.g, i.e, No, Jan…Dec, U.S, U.K, U.N, E.U, a.m, p.m, nor after single capital initials ("J. R. R. Tolkien").
- Very long sentences (> 400 chars) may be soft-split at the `；;，,、` nearest to the middle.

### 6.3 Japanese (`nlp/ja.js`, kuromoji)
- One kuromoji token = one word (`w`), except POS `記号` (punctuation) and whitespace → plain tokens without `w`.
- Furigana alignment for a token with kanji (Han, `々`, `〆`, `ヶ`): reading = katakana→hiragana of `token.reading`; split the surface into runs (kanji-run / kana-run / other); build regex `^…$` where kanji-run → `(.+?)`, kana-run → its hiragana form (escaped), other → escaped literal; match against the reading → each kanji-run gets its captured reading; on no match → whole surface gets the whole reading. No `r` when the token has no kanji, or reading is missing/`*`. Digits never get `r`.
- Expected: 食べる → 食[た]べる; 今日 → 今日[きょう]; 取り組み → 取[と]り組[く]み; 人々 → 人々[ひとびと]; 学んだ (tokens 学ん + だ) → 学[まな]ん + だ; 3日 → "3" no ruby, 日 has a ruby.
- `words`: lemma = basic_form (or surface if `*`), reading = hiragana of the whole token reading; POS map: 名詞→n; 動詞→v; 形容詞, 副詞, 連体詞→a; 助詞, 助動詞, 接続詞→p; others (接頭詞, 感動詞, フィラー, その他)→x.

### 6.4 Chinese (`nlp/zh.js`, jieba-wasm + pinyin-pro)
- Display script: converted earlier per `zh_script` (opencc), so NLP sees the final text.
- Segment with `tag(sentence, true)` → `[{word, tag}]` (concatenation equals the sentence; assert/repair).
- For each word: pinyin-pro `pinyin(word, {type:'all', toneType:'symbol'})` → per character; Han characters → token `{s: ch, r: pinyin, w}`; consecutive non-Han characters inside a word → one token `{s, w}` without `r`; words consisting only of punctuation/whitespace → tokens without `w`.
- `words`: lemma = word, reading = syllables joined by spaces; POS map (jieba tags): n, nr, ns, nt, nz, ng, nrt, vn, t, s → n; v, vd, vg, vi → v; a, ad, an, ag, d, b, z → a; p, c, u, uj, ul, uz, ud, ug, uv, y, e, o → p; others (m, q, r, f, x, w, eng, …) → x (punctuation-only words → no `w`).
- Expected: 银行 → yín háng; 行走 → xíng zǒu; 重要 → zhòng yào; 重复 → chóng fù.

### 6.5 Korean (`nlp/ko.js`, own code)
- Split on whitespace into eojeol; leading/trailing punctuation → separate tokens without `w`.
- Particle split: if the eojeol ends with a particle from this list (longest first): 에서는, 에게서, 으로서, 으로써, 에서도, 까지는, 부터는, 이라고, 에서, 에게, 한테, 께서, 으로, 처럼, 보다, 까지, 부터, 라고, 와, 과, 은, 는, 이, 가, 을, 를, 에, 의, 로, 도, 만 — split stem + particle when (a) the stem is ≥ 2 syllables, or (b) an injected `hasWord(stem)` (dictionary) returns true. Stem → word pos `n`; particle → word pos `p`; unsplit eojeol → pos `x` (function-word list not needed).
- Romanization (when `ko_roman`): Revised Romanization with pronunciation rules applied within each piece: liaison (final consonant + ㅇ-initial syllable), nasalization (ㄱ/ㄷ/ㅂ before ㄴ/ㅁ; ㄱ/ㅂ + ㄹ → ㅇ/ㅁ + ㄴ; ㅁ/ㅇ + ㄹ → ㄴ), liquidization (ㄴ+ㄹ, ㄹ+ㄴ → ㄹㄹ), palatalization (ㄷ/ㅌ + 이 → 지/치), aspiration with ㅎ, final-consonant neutralization (ㄱ/ㄲ/ㅋ→k, ㄷ/ㅅ/ㅆ/ㅈ/ㅊ/ㅌ/ㅎ→t, ㅂ/ㅍ→p), ㄹ → l at the end/before consonant and r before vowel, ㄹㄹ → ll. Lowercase, no hyphens. Expected: 독립→dongnip, 신라→silla, 같이→gachi, 정치→jeongchi, 한국어→hangugeo, 합니다→hamnida, 대한민국→daehanminguk.
- Token per piece: `{s: piece, r: roman, w}`.

### 6.6 English (`nlp/en.js`)
- Words = `/[\p{L}\p{M}][\p{L}\p{M}'’\-]*|\p{N}+(?:[.,]\p{N}+)*/u`; everything else (spaces, punctuation) → tokens without `w`. No `r`.
- lemma = lowercase surface; pos `p` for a small function-word list (the, a, an, of, to, in, on, at, by, for, with, from, and, or, but, as, that, which, who, is, are, was, were, be, been, it, this, these, those, not), else `x`.
- Lookup candidates (in lookup.js): surface, lowercase, strip `'s`, -ies→y, -es, -s, -ed/-d, -ing (+e), -er/-est.

### 6.7 Translation
- `google_free`: `POST https://translate.googleapis.com/translate_a/single?client=gtx&sl=<src>&tl=<tgt>&dt=t&dj=1`, body `q=<urlencoded>`, header `Content-Type: application/x-www-form-urlencoded;charset=UTF-8`. Result = concatenation of `sentences[].trans`. (Use `direct` fetch on PC only if env_report.md says the response carries `Access-Control-Allow-Origin: *`; otherwise via proxy. Native: CapacitorHttp.)
- Batching: per block, join its sentences with `\n` (each batch ≤ 4 500 chars; split big blocks); split the result on `\n`; if the count differs from the number of inputs → translate those sentences one by one. At most 2 requests in flight globally; 429/503 → wait 2 s, 4 s, 8 s; after 3 consecutive failures set `tr_state:"paused"` and show “⚠ Dịch tạm dừng ↻” in the reader toolbar.
- Skip translation when source language == target language (`tr` = "").
- `openai_compat` (optional): `POST <oa_base_url>/chat/completions` `{model, temperature:0.2, messages:[{role:'system', content:'Translate each input sentence from <src> to <tgt>. Reply with ONLY a JSON array of strings, same length and order as the input.'},{role:'user', content: JSON.stringify(sentences)}]}` with `Authorization: Bearer <oa_key>`; validate the array length; on any failure fall back to google_free for that batch.
- Title is translated first (needed by the suggestion card and the history).

### 6.8 Recommendation and lifecycle
- Build a shared eligible pool for suggestions and home statistics. Include only status `new`, languages in `settings.langs`, enabled sources, overlapping topics, and links/series absent from history and skips. For a series, consider only its first eligible chapter by `seq` before checking length. Known `est_chars` must fit `settings.length`; unknown length is eligible for validation.
- `getSuggestion(filter)` combines a language and a category filter. Restore the validated suggestion pinned to that combination when it still matches. Otherwise reuse the current suggestion if it matches. Remember the suggestion canons and the active selections in `state`.
- When the language filter is `all`, prefer the language whose latest `history.finished_at` is oldest (never read = oldest); break ties randomly. For each language, rotate news → encyclopedia → literature → news, remembering the last published category in `state` and skipping empty categories. Within news, take the newest publication; within other categories pick randomly among eligible items.
- Validate in two steps. (1) Fetch and extract the body, excluding a duplicated title. Save the body character count in `est_chars`. Mark extraction failures or bodies below 800 chars (ja/zh/ko) or 1,500 chars (en) as `bad`. A body outside the selected length remains `new` with its measured length. Try up to eight candidates per request. (2) Publish only a passing candidate and use the extracted body to open it in the background. Run NLP and prefetch translation for the title and the first 20 sentences. Continue the remaining translation in the reader.
- A validated suggestion stays fixed until read or skipped while it still matches the active filters. `skipSuggestion()` records the canon or `series:<source_id>` for a series, deletes the cached article, and clears its suggestion.
- `finishArticle(id)` requires `progress.last_read >= total - 1`, otherwise throws `NOT_FINISHED`. Append to the durable ledger, mirror the entry in history, delete the cached article, and clear its suggestion. `abandonArticle(id)` applies the same skip rules to the open article.
- Pasted links follow the same finish flow and enter history.

### 6.9 Pool refresh (`jobs.js`, `sources/*.js`)
- Adapter interface: `refresh(source, ctx) → Candidate[]` (`ctx = {net, now, settings, db, signal}`). Refresh runs when forced or the last refresh is at least six hours old. App start, Android resume, PC focus and the refresh button trigger it.
- Refresh enabled sources with concurrency three and a 30-second deadline per source. Record timeouts and errors in `source_status`, continue with the other sources, and emit completed/total progress followed by `running: false`.
- Take at most 25 new candidates per language on every refresh, including the first, by cycling through that language's enabled sources. Skip duplicate canons and links or series already read or skipped. Preserve existing status, measured length, and fetched time.
- Expire news fetched over 14 days ago. Cap each language at 75 unread candidates (status `new`, absent from history and skips). Evict oldest-fetched news first, then the oldest remaining candidates. Protect current suggestions and articles that are cached or in progress; protection takes precedence if none of the remaining candidates can be evicted.
- RSS and Atom supply valid entries newest-first by publication time.
- Wikipedia search requests `srsort=random&srlimit=50&srnamespace=0&srprop=size` with the configured query. Discard results below 6,000 wikitext bytes and, for short or medium, results above 60,000 bytes. Leave `est_chars` unknown until body extraction. The featured endpoint supplies at most one featured item for the current date.
- Wikisource series extract the ordered chapter links from the index page HTML and cache the list. Supply candidates with `series = source.id`, `seq = 1..n`, and a chapter URL. Refresh can add remaining chapters under the same quota.
- Aozora downloads its ZIP catalog at most every 30 days and caches the filtered public-domain author rows in `state`. Parse quoted CSV in chunks that yield to the event loop, then filter by the configured NDC prefixes and offer the rows in random order. The work title is followed by the author, with NDC 2xx mapped to history and 9xx to literature.

### 6.10 Lookup and popup
- `lookupWord({lang, lemma, surface, reading})`: dict entries for the language, trying lemma → surface → alts → reading (ja) → (ko) longest prefix of the surface down to 1 syllable → (en) §6.6 candidates → (zh) if nothing, per-character entries. Return `{entries:[{head,alts,reading,pos,senses,gloss_lang,source,license}]}` (max 3 entries, 5 senses each).
- Quick online translation per `quick_tr` (auto: only when entries are empty; always; off) via `quickLookup`.
- Popup content: the word (large) + reading (from `words[w].reading`, or dict reading) + lemma if different + POS label (danh từ / động từ / tính từ–trạng từ / hư từ / khác) + entries (tag "Việt"/"Anh" by gloss_lang) + "Dịch nhanh: …" + footer "Nguồn: <name> (<license>)".
- Opening rules: only when `lookup` is ON; on `pointerup` within 500 ms of `pointerdown`, movement < 8 px, and no scroll in the last 250 ms; target = closest `.w`. Highlight the word. Close on ✕, tap outside, Esc, Android Back, or scroll > 30 px. One popup at a time. Width < 700 px → bottom sheet; otherwise a floating card next to the word, kept inside the viewport.

### 6.11 Reading progress
- IntersectionObserver on sentence blocks; `last_read` = max `i` seen (≥ 60 % visible or passed). Save debounced 2 s and on `visibilitychange`/`pagehide`. On open, scroll to `last_read`.
- "✓ Đã đọc xong" enabled only when `last_read >= total - 1`; tooltip otherwise: "Kéo tới câu cuối để hoàn thành".

## 8. PC shell
- `pc/server.py` (stdlib only: `http.server.ThreadingHTTPServer`, `urllib.request`, `ipaddress`, `socket`, `json`): bind `127.0.0.1`, port `DSN_PORT` env or 8765. Reject requests whose `Host` is not `127.0.0.1:<port>`/`localhost:<port>` (DNS-rebinding guard).
- Static: serve `web/` with correct MIME (`.js/.mjs` text/javascript, `.wasm` application/wasm, `.json`, `.svg`, `.gz` application/octet-stream WITHOUT Content-Encoding), `Cache-Control: no-cache`.
- `/proxy?url=<encoded>` GET/POST: require header `X-DSN: 1` (blocks other websites from using it); only http/https; resolve the host and refuse loopback/private/link-local/reserved addresses, also on every redirect hop (custom redirect handler); forward body and the whitelisted headers passed in `X-Proxy-Headers` (JSON: Accept, Accept-Language, Content-Type, User-Agent, Api-User-Agent, Referer, Authorization); default browser-like User-Agent; timeout 20 s; max 10 MB; respond 200 with the upstream bytes, `Content-Type` passthrough, `X-Proxy-Status`, `X-Proxy-Final-Url`; on failure 502 JSON `{"error": "..."}`. Never log headers or bodies.
- `/api/history` GET/POST (4.3) on `data/da_doc.jsonl` (create `data/` if missing). `/api/ping` → `{"ok":true,"app":"docsongngu"}`.
- `run.bat`: `chcp 65001`; cd to its folder; if `/api/ping` answers → just open the window; else if `web\vendor` is missing → run `npm run vendor` once (needs node_modules) and stop with a clear message if that fails; start the server minimized (`start "Đọc Song Ngữ (đóng cửa sổ này để tắt)" /min py -3 pc\server.py`), wait until ping answers (≤ 5 s), then `start "" msedge --app=http://127.0.0.1:8765/`.
